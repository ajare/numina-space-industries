# Lua lifecycle stage before native playback physics

**Status: Accepted.** Editor playback runs the existing four budgeted lifecycle/mirror sandboxes once per requested 10 Hz host update, before native Cell gas/thermal processing. This restores the scripted lifecycle boundary without constructing `StationSystemsRuntime` or running its authoritative C++ compartment/plant ledger alongside native transport. Native acoustic/source/thermal numerical loops remain C++ only, as required by ADR-0004.

`StationLifecycleRuntime` reuses the standalone runtime's factory marshalling, private environments, budgets and acknowledgement validation. Its immutable descriptors include the atmospheres and solar profile currently supplied by Installation expansion. The bundled compartment mirror remains independent: it does not receive spatial Door/Cell fluxes or compare its private inventories against the native state, and it does not actuate native equipment. This is lifecycle/mirror integration, not complete plant integration or an assertion that the mirror audits CFD.

The stage prepares all four Lua acknowledgements, then native physics attempts the same duration. Public counters/time commit together only after physics succeeds; snapshots expose only committed acknowledgements. A successfully prepared private Lua candidate is retained across a same-duration physical refusal so retry cannot execute the script step twice. Script errors retire partially mutated sandboxes. Recovery, or changing a prepared duration, reconstructs the immutable source/configuration and replays the committed duration journal. Recovery is bounded to 4096 committed steps by default and refuses explicitly beyond that budget; no committed state or requested time is discarded. Reset reconstructs both stages. The standalone runtime's existing failure/retirement policy is unchanged.

**Power-only exception (#65).** The prohibition on constructing `StationSystemsRuntime` above is narrowed for the isolated solar-array bus required by #59. An optional, separate runtime contains only one derived array and its consumer-less bus: no atmospheres, thermal reservoirs, Hull, loads or native inventories. It advances only after a successful native step, using the same duration and the bridge's midpoint authored-sky input. The Editor copies only its power snapshot, never its clock or gas/heat state. This reuses the authoritative unclipped generation and disabled state rather than duplicating the formula in the GUI. Reset reconstructs it; a disposable next-10-Hz-tick preview supplies edit-time readouts without advancing the committed playback clock.

Variable-duration hosts supply an optional committed start-time argument to `advance(self, tick, seconds, startSeconds)`. The bundled script uses it instead of multiplying step number by the newest duration; three-argument legacy callers retain their previous behaviour. Custom wrappers must forward the start-time argument if they delegate variable-duration schedule work to the bundled method.

Timing now records lifecycle preparation/recovery and native gas/heat separately, retaining 50 successful update samples for the left-inspector stacked chart (five seconds at 10 Hz). The rolling ten-update average sums these stages, excluding construction, diagnostics, observation publication, controller history and GUI work. Paused/failed/zero-duration calls add no samples. Private Lua allocations remain governed by the existing sandbox budget. Numerical stepping retains its preallocated-buffer contract; the combined lifecycle tick is not claimed to be allocation-free.
